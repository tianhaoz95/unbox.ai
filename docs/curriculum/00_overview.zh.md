# 课程概览

本课程涵盖从头构建大语言模型的完整流程 —— 从原始互联网文本，到可部署的指令跟随模型，再到生产级推理 API。每一章既是设计文档，也是实现指南：着重解释每个决策背后的**原因**，而非仅仅描述**做了什么**。

## 完整流水线

```mermaid
graph LR
    A[原始网页文本] --> B[数据清洗]
    B --> C[分词器训练]
    C --> D[预训练]
    D --> E[监督微调]
    E --> F[强化学习后训练]
    F --> G[推理引擎]
    G --> H[API 服务]
```

## 设计原则

**简洁优于极限性能。** 每个组件都以可读性和可修改性为首要目标。目标吞吐量约为业界水平的 50%；最后 50% 的性能需要工程复杂度的大幅提升，反而会掩盖底层的核心思想。

**配置驱动。** 所有实验通过 YAML 配置文件与类型化 dataclass 指定。不允许在代码中硬编码超参数。

**复用而非重造。** 工业级框架（PyTorch、Megatron-Core、TRL）是一等依赖。自定义代码构建在它们之上，而非重新实现其底层逻辑。

**单文件组件。** 一个注意力模块、一个调度器、一个采样器 —— 每个都独立存放于一个文件中，可单独阅读和修改。

## 框架选型

| 子系统 | 框架 | 选型理由 |
|---|---|---|
| 预训练 | PyTorch + Megatron-Core | 内置 TP/PP/SP 支持 |
| HF 兼容性 | `transformers` 适配器（`UnboxForCausalLM`）| 无需修改核心模型即可接入 TRL、PEFT 和评测工具 |
| 监督微调 | TRL `SFTTrainer` | 业界标准；自动应用对话模板 |
| 离线 RL | TRL | 与 SFT 同一生态系统 |
| 在线 PPO | OpenRLHF | 生产级 rollout 循环 |
| 推理算子 | Triton | Python 原生；无需 CUDA |
| 推理 IPC | ZMQ | 前端-工作进程及 KV 传输通信 |
| 推理 TP | NCCL | 与训练相同的 all-reduce 集合通信 |
